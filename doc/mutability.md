# Мутабельность

## Введение
В этом разделе описана функциональность, добавленная в проект Rukaml в рамках учебной практики третьего семестра. Конкретно, рассматривается реализация массивов и типизации мутабельных значений.

## Типизация мутабельных значений
### Реализация
Появилась в [PR 18](https://github.com/Kakadu/rukaml/pull/18).

Вводится сущность "слабых типов", которые служат прослойкой между полиморфизмом и мономорфизмом. Все они нумеруются для различия и обозначаются `_weakN`, где `N` - целое число.

Для типизации мутабельных значений используется подход Relaxed value restriction, который можно описать так:
1) Если есть инициализация мутабельности или частичное применение функции, заменяем параметрические типы на слабые, иначе возвращаем полиморфизм, если слабые типы находятся только в правой стороне от стрелки (тип функции) или тип не имеет стрелок вообще.
2) Заменяем слабые типы на мономорфные, если есть информация о том, какие соответственно типы они принимали.

В коде `/front/inferencer.ml`, функции `restrict` и `elim` выполняют пункт 1 и 2 соответственно.

Код с выводом типов имеет хорошое тестовое покрытие (71%), отсутствуют регрессии.

### Значение
1) Обеспечивает безопасность типов в окружении мутабельности.
2) Типизирует больше программ по сравнению с традиционными методами (например, Standard ML 90)

## Массивы
### Мотивация
- Появилась потребность в примере мутабельного значения
- Интеграционное тестирование типизации
- Расширение возможностей языка

### Реализация
Появилась в [PR 18](https://github.com/Kakadu/rukaml/pull/18) и [PR 22](https://github.com/Kakadu/rukaml/pull/22), последний прошёл CI.

Написана на С под две целевых архитектур - RV64 и AMD64. Код находится в файлах `/back/(rv64|amd64)/rukaml_stdlib.c`.

Массив из `N` элементов аллоцируется массивом из `N+1` элементов-указателей, где первый элемент является заголовком, который хранит тег для различия (`Array_tag`) и значение `N`. Как и кортежи, массивы освобождаются встроенным сборщиком мусора.

### Changelog
- Массивы можно создавать через конструктор `[|...|]`
- Чтение/запись осуществляется с помощью функций `get` и `set`, для них же есть синтаксический сахар `.()` и `.() <-`
- Добавлен тип `char`
- Синтаксический сахар для массивов из символов `"string" = [|'s', 't', 'r', 'i', 'n', 'g'|]`
- Можно читать текст из файла и stdio через функции `open_in` и `stdin` соответственно и получить результат в виде `char array`
- Для тестирования предыдущего пункта были введены новые команды для DSL `testsuite`, подробности есть в `testsuite/README.md`
